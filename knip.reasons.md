# Why each `knip` exemption exists

knip reports genuinely dead code. Every entry below is therefore a **claim that something is not dead
yet**, and each must name what will make it live. An exemption with no expiry is how dead code becomes
permanent while looking supervised.

**This list may only shrink**, and a test asserts it matches `knip.json` exactly.

**2026-09-10 — five exemptions removed, and how they were found.** `@supabase/ssr`,
`@supabase/supabase-js`, `server-only`, `@testing-library/react` and `@testing-library/jest-dom` were
all past the expiry written in their own "Removed when" column: SPEC-004 shipped and wired the
clients, and `.dom.test.tsx` files exist. They sat here anyway, because **nothing reads this column**
— the ratchet caps how many exemptions there are, not whether any has outlived its reason. knip
itself had been printing `Remove from ignoreDependencies` for each of them under _Configuration
hints_, on every run, where the gate passed green and nobody looked. The `unused` gate now fails on
those hints, so the tool's own answer to "is this exemption still needed?" stops being advisory.

| `src/lib/supabase/**`          | The three clients are written and **imported by nothing** — genuinely orphaned by the project's own no-orphan-stubs rule. Tracked as **DEF-004**, whose trigger fires when SPEC-004 is done.                                                                                                 | SPEC-004 wires them          |

| `src/lib/env.ts`               | The validated-environment loader. Consumed by the Supabase server clients, which are themselves exempted under DEF-004 — so knip sees a chain that reaches nothing. Not dead: it is one import away from live, and it already validates on every server boot once anything imports it.                                                                                                             | SPEC-004, with DEF-004       |
| `dotenv`                       | Used by tooling that reads `.env.local` outside the Next runtime.                                                                                                                                                                                                                                                                                                                                  | —                            |
| `tailwindcss`                  | **False positive.** Consumed through `postcss.config.mjs`, which knip does not trace.                                                                                                                                                                                                                                                                                                              | knip learns PostCSS configs  |
| `src/lib/db/database.types.ts` | **Generated**, not written — `npm run generate` produces it from the live schema, and the `generated` gate fails when it drifts. Imported only by the Supabase clients, which are themselves exempted under DEF-004, so knip sees a chain reaching nothing. It is the opposite of dead: it is the artifact that stops a renamed column from compiling cleanly and being `undefined` in production. | SPEC-004, with DEF-004       |
| `src/components/ui/**`         | **Vendored, not written.** shadcn components are copied in by the CLI and stay upstream-equivalent so `shadcn add` can replace them (ADR-023). knip flags `buttonVariants` as an unused export, and it is — upstream exports it for consumers. Editing the file to satisfy a linter is precisely the fork the discipline forbids, so the directory is exempt instead of the code being changed.    | keelblock stops using shadcn |
| `shadcn`                       | **False positive**, same class as `tailwindcss`. `globals.css` does `@import 'shadcn/tailwind.css'`, and knip does not follow `.css` imports — it says so itself in the remaining configuration hint. Removing it was tried and broke the build, which is the evidence that it is load-bearing rather than a CLI left in the manifest.                                                             | knip follows CSS imports     |
| `psql`, `supabase` (binaries)  | Real **system** prerequisites, not npm packages — knip cannot see them. Their absence is now a documented prerequisite, and `check` fails with an actionable message rather than a stack trace.                                                                                                                                                                                                    | —                            |
