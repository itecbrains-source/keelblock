# SPEC-032: keelblock.dev — the project's own site, and the pipeline that publishes it

> Status: `draft` · Research: [`research/15-SITE-PIPELINE.md`](../research/15-SITE-PIPELINE.md) · ADRs: [024](../docs/adr/ADR-024-deploy-topology.md), [009](../docs/adr/ADR-009-open-core-boundary.md)
> Contracts: SPEC-002, SPEC-012 ·

## Intent

`docs/WEBSITE-AND-DOCS.md` has planned keelblock.dev in detail — seven landing sections, five
documentation sections, a material pipeline that routes every finding the day it is produced — and
has said, in its own opening, that **no spec claims it**: "It is a plan, and plans are not gated."
This spec claims it. After this ships, the site has acceptance criteria, its content source is
decided rather than unspecified, and the gap F-69 recorded — a gate proving a destination was NAMED
while nothing proves it EXISTS — becomes checkable instead of structural.

The site matters for one reason, and it is not marketing. keelblock's only differentiated asset is
**evidence a stranger can check without trusting us**, and the access matrix is the single artifact
no competitor in this field can publish, because publishing it requires having done the measurement.
A plan cannot render that page. This spec is what makes it a deliverable.

## Scope / non-scope

- **In scope:** keelblock.dev itself — the landing page, the published documentation, the rendered
  proof page, the blog that carries `FINDINGS.md`, and the content pipeline all four run on.
- **Out of scope, and named so it is a decision:**
  - **Bars B-5 and B-8 are not claimed here.** They belong to SPEC-012 (docs a buyer receives) and
    SPEC-009 (the marketing shell a buyer receives). keelblock.dev is a **different artifact** — the
    project's own site, not a kit feature — and inheriting a buyer's bar for it is precisely the
    confusion F-69 exists to end. This spec owns no acceptance bar and says so.
  - **A live demo** is DEF-032 and is not v1. `WEBSITE-AND-DOCS.md` borrows supastarter's finish as
    the bar — "clear writing, a real demo, honest changelog, working search, no dead links" — and
    one of those five is a deferral, not a criterion. Named here so the bar is not quietly reported
    as met.
  - **Blog machinery as a kit feature.** `PRODUCT.md` refuses it. This project publishing posts and
    the kit shipping no blog machinery are opposite sides of one boundary, not a contradiction.
  - **The Vercel account wiring.** ADR-024 decided the topology; linking the project and adding
    `VERCEL_TOKEN` is an owner action, not a requirement this spec can satisfy.

## Requirements

### REQ-1 — The content source is named, and it is the one that ships with the framework

`@next/mdx` is versioned in lockstep with Next itself — 16.3.4, the exact version this repository
pins, published within a week of the memo's reading. Nothing else in the category has that property.

Without this the site has no content source at all, which is today's state, and the plan stays a
plan. The alternatives were measured rather than assumed (memo 15): Nextra's last publish is nine
months old with a peer range that never mentions 16, and Contentlayer2's is sixteen months old —
both of which a web search still recommends. **A spec that took the summaries would have chosen an
unmaintained package and looked diligent doing it.**

### REQ-2 — Every remark/rehype plugin is declared in the serializable form Turbopack accepts

Next.js 16.3.4's own documentation: _"remark and rehype plugins without serializable options cannot
be used yet with Turbopack, because JavaScript functions can't be passed to Rust."_ This repository
builds with Turbopack on every run. Plugins must be named as **strings** with serializable options.

Without this, the setup every tutorial shows — import the plugin, pass the function — is refused by
the build. The requirement exists because the failure is invisible until someone copies the ordinary
example, which is what everyone will do.

### REQ-3 — The proof page renders the generated matrix and links the run that produced it

Landing section 2, in the plan's own words: _"The live access matrix, rendered. The 'different
organization' column is the whole pitch. Link to the CI run that produced it."_ The page renders
`docs/ACCESS-MATRIX.md`, which is generated by probing the live policy catalog, and carries the run
identifier and timestamp of the CI job that produced that content.

Without the link, the page is a picture of a table and the reader has to trust it — which inverts
the only thing keelblock claims. A proof page a stranger cannot check is worse than no proof page,
because it looks like evidence.

### REQ-4 — The `⚠` rows are surfaced, not buried

`ACCESS-MATRIX.md`'s legend marks `⚠ behavior differs from the policy's intent`. Those rows are
surfaced on the page rather than left to be found mid-document.

Without it the page publishes only its wins, which is the failure `WEBSITE-AND-DOCS.md` names as
disqualifying: _"a project claiming rigor that publishes only its wins is doing marketing."_ The
rows that disagree with intent are the reason the page is believable.

### REQ-5 — A routed destination that exists is checked, and the check arrives with the first publishable row

F-69: `check-content` proves every finding HAS a destination and nothing proves the destination
EXISTS, "so it will keep passing indefinitely while nothing is published." That gate could not be
written before this spec, for a recorded reason — the strict rule fails on every blog-routed row on
the day it lands (ADR-023's standard), and the weak rule is vacuous until publishing starts (F-13).

Once a pipeline exists, the rule stops being ungateable: a destination that exists is checkable the
moment there is somewhere for it to exist. **The rule ships with the first published row, not
afterwards**, because "we will add the gate later" is the sentence F-65 and F-67 were both written
about.

### REQ-6 — Every number on the site links to the run that produced it, and no social proof is fabricated

Transcribed from the plan's Rules, unchanged: never claim what is not measured; no stock avatars, no
invented counts, no "trusted by"; the changelog includes what we got wrong.

Without it the site becomes the kind of artifact this repository spent seven commits removing from
its own documentation — a claim whose evidence nobody opened. An empty testimonial section is worse
than none, and inventing one would break the rule the whole project rests on.

### REQ-7 — The site has no dead links

The plan's borrowed bar includes it, and it is the one item on that list that is purely mechanical.

Without it the failure is specific rather than cosmetic: the proof page's whole value is a link to a
CI run, the Evidence section links findings to reproductions, and a dead link there is a claim with
its evidence removed.

## Deferrals

**Search is expected to be deferred, and the reason is a real tension rather than a shortage of
time.** The plan's borrowed bar asks for working search. Pagefind is the obvious answer — static,
free, no API key, no query logging — and it indexes **static HTML output**, which it states it
requires and which it cannot do for server-rendered content. ADR-024 chose Vercel over static
hosting deliberately, and every route in this repository currently builds as `◐ Partial Prerender`.

Those do not obviously compose. Memo 15 declines to resolve it and this spec follows:
search gets its own row when the pipeline exists and the shape of the built output is a fact rather
than a projection. Deciding it now would record a choice nobody has made — DEF-001's objection, and
it was right.

A live demo is **DEF-032**, already filed, and is not v1.

## Definition of Done

- [ ] Every REQ `done` with its AC passing, or covered by an open `DEF-*` with a machine-evaluable trigger.
- [ ] Cheap gates green: `npm run check`.
- [ ] The research memo re-verified on the date of build, and its date moved only by someone who re-read the sources. Memo 15 is `fast` volatility — 90 days — and it says in as many words that it was not built, so the first spike is expected to correct it.
- [ ] **Written up.** A `differentiators` entry in `docs/content/MANIFEST.json`, or a `$noDifferentiator` entry saying why this ships nothing worth claiming.
- [ ] **Documented.** A `documentation` entry in `docs/content/MANIFEST.json`, or a `$noDocumentation` entry with its reason.
- [ ] `docs/WEBSITE-AND-DOCS.md`'s opening no longer says that no spec claims it, because one does.
